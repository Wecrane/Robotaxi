# 比赛实时预览与手动接管设计

## 目标

在 `debug=false` 的实车模式下，通过 SSH X11 显示持续更新的四合一画面；Windows 手动接管做到按下立即生效、松开立即停车，并在网络异常时可靠停车。

## 四画面

启用 `showCamera` 时创建一个 `ICAR Live` 窗口，按 2×2 排列：

1. `Original`：校正后的彩色原图。
2. `Binary`：赛道二值化图。
3. `Track`：在彩色图上绘制左右道路边缘。
4. `Control`：叠加道路边缘、目标检测框、拟合控制路径、速度和舵机信息的最终控制图。

显示逻辑与 `debug` 解耦，不切换到本地视频、不启用调试帧滑条，也不改变实车控制分支。每帧只在所有处理和控制计算结束后刷新一次。

摄像头已按正确方向安装，X11 四合一预览和 Windows 手动画面均直接显示收到的图像，不做任何 90° 方向旋转。`predeal->correction()` 继续保留，它只负责相机标定、畸变和裁剪矫正。

## 手动控制协议

Windows 客户端以固定周期发送当前完整按键状态，而不是只在按键变化时发送。方向状态约每 30 ms 发送一次；`STOP`、退出和松键事件走高优先级路径。TCP 发送仍在独立线程中执行，队列只保存最新状态，但不得覆盖尚未发送的紧急停车。

Windows 手动客户端不创建 OpenCV 摄像头窗口，比赛时始终观看 `start.py` 启动的 X11 四合一窗口。客户端只负责键盘采集、命令发送和终端状态提示。

服务端按换行拆分命令，收到每个合法命令时更新时间。手动控制 TCP 链路不再编码或发送 JPEG 图像，只发送轻量车辆状态与接收控制命令，避免图传占用 CPU、带宽或增加控制延迟。

## 失效安全

- 客户端周期发包，服务端超时缩短到约 300 ms。
- 断线、接收错误或超时后，服务端立即清除方向状态并置紧急停车。
- 手动接管状态保持停车，重新连接后必须重新按键才运动；不因断线自动恢复自动驾驶。
- `RETURN` 是唯一恢复自动驾驶的指令。
- 客户端关闭前同步尝试发送 `STOP`，然后关闭 socket。

## 线程与生命周期

服务端单个连接的收发线程必须可控退出并在连接结束前回收，避免 detached 线程跨连接访问复用的 socket。共享 socket 状态和控制状态通过明确的锁或原子状态保护。
